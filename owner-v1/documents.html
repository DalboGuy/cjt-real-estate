Cloud Document Center

The portal will organize and surface documents while the authoritative files stay in cloud storage.

Plan recorded

Design principle

Keep large files out of the application database whenever practical.

Cloud first
The Owner Portal should act as a searchable index and operating layer. Documents remain in the selected cloud provider, and the portal stores the document name, category, cloud link/ID, source, property/reservation/vendor relationships, dates, tags and access metadata.

Automatic document intake

Preferred path: documents arrive without someone manually uploading them.

Planned
Email attachmentsGmail rules identify invoices, statements, contracts, receipts and vendor documents, save them to cloud storage, then index them here.
Generated reportsOwner statements, financial reports and exports can automatically save a cloud copy when generated.
Reservation documentsSigned rental agreements and booking-related documents should attach to the matching reservation automatically when possible.
Vendor / maintenance recordsInvoices, warranties and service records should route to the property, vendor and maintenance item based on email/source metadata.
Manual uploadAvailable as a fallback, not the normal operating method.

Planned automation flow

How a document should get from an outside source into the portal.

1 · DetectEmail, generated report, signed contract, connected cloud folder or manual fallback.
2 · ClassifyDetermine document type, property, reservation, vendor, statement period and useful tags.
3 · FileSave or confirm the authoritative copy in the configured cloud location.
4 · IndexWrite a lightweight portal record with cloud pointer, metadata and relationships.
5 · SurfaceShow the same document from Reservations, Financials, Maintenance, Vendors or Documents without duplicating the file.
